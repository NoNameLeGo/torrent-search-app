## 1. 评估口径

### 1.1 项目侧的四道硬门槛（从代码里读出来的，不是猜的）

| # | 门槛 | 依据 |
|---|---|---|
| 1 | 结果要能映射成 `TorrentResult` | `crates/bt-core/src/normalize.rs:519`：`name` / `size` / `seeders` / `date` / `magnet` / `info_hash` / `detail_url` / `needs_magnet` |
| 2 | **必须有服务端渲染的搜索入口** | 项目没有 headless 浏览器；`bt_core::dom` 只解析服务端返回的 HTML |
| 3 | **必须能拿到 `magnet:?xt=urn:btih:` 或 info_hash** | `TorrentResult` 没有 `.torrent` 字段；全仓 `grep bencode` = **0 命中** ⇒ 只给种子文件的站要新增核心能力 |
| 4 | 不能要登录 / 验证码 / 人机验证 | 现有 24 家全是匿名可抓；`Provider::search` 没有凭据参数 |

另外两条流程成本：

- 新增 provider 要进 **M6 差分门**（`m6-diff.yml`）+ 离线 fixture + 探针，工作量不止写解析器；
- 参考体量：`dmhy.rs` 230 行、`anirena.rs` 260 行、`nyaa.rs` 353 行。

### 1.2 五个维度

| 维度 | 本次怎么测 |
|---|---|
| 可访问性 | 本机 HTTP 状态、响应时间、是否跳转到新域名（域名漂移信号） |
| 内容质量 | 是否有真实条目、磁力是否带片名/规格/体积、是否同模板复制 |
| 分类相关性 | **能否产出 magnet/info_hash**（不是「能不能看片」） |
| 维护状态 | 搜索入口是否稳定、是否 SPA、是否 Cloudflare/人机验证、是否限流 |
| 潜在风险 | 版权、广告/跳转、登录墙、推广参数、域名寿命 |

### 1.3 局限（先说清楚，免得被当结论滥用）

- 单机、单网络、单次采样（16:57–17:12）。**「本机 200」不等于「长期可用」**，也不等于「你所在网络可用」。
- 没有逐站播放验证，所以在线影视的「画质/片源」未评；只评了「能不能成为 BT 源」。
- 不构成法律意见。版权风险只做事实描述，不给规避建议。

### 3.2 推荐 ①：BD电影首发（bdflixs.com）

**实测证据**

- `GET https://www.bdflixs.com/?s=流浪地球` → 200，标题「「流浪地球」的搜索结果」，命中 2 个影片页。
- 影片页 `/594.html`（WordPress 数字 ID）→ **102 条唯一 magnet**，锚文本直接带片名、规格、体积：
  `流浪地球[HDR+杜比视界双版本][国语音轨+简繁英字幕].2019.2160p.UHD.BluRay.x265.10bit.DV.TrueHD.7.1.Atmos-QuickIO - 26.02GB`
- 第二个影片页 `/595.html` 同样有 99 条。

**可映射字段**：`name` ✅、`size` ✅（从锚文本尾部 `- 26.02GB` 解析）、`magnet` ✅、`detail_url` ✅、`date` 部分（片名里的年份）、`seeders` ❌。

**优点**

- 磁力密度最高：一个影片页就是一份完整发布列表，规格/体积都在锚文本里。
- 中文片名完整，和现有英文站互补；匿名可抓，无登录墙。
- WordPress 结构稳定，`?s=` 是标准搜索参数。

**缺点**

- **列表页没有磁力**：搜索只回影片页，必须「搜索 → 详情 → 展开磁力」两步。一个搜索词 2 个影片页就是 3 次请求；热门词可能更多。
- 没有 seeders/leechers，排序会缺一列。
- 单域名、无发布页备份；页面有广告。
- 无分页链接（实测 `paged=2` 直接报错），只能做单页 provider（`paginated() = false`）。

**落地建议**

- 按 `needs_magnet` + `resolve_magnet` 实现：列表只回影片条目，用户点某条时再抓详情页展开磁力。
- 或者 provider 内做 1+N 展开，但**必须限 N（建议 ≤5）并并发**，否则单站延迟会拖垮聚合层。
- 体量参考 `dmhy.rs`（230 行），预计 200–260 行 + fixture。

### 3.3 推荐 ②：POMO（pomo.mom）

**实测证据**

- `GET https://pomo.mom/?keyword=流浪地球` → 200，结果卡片命中「流浪地球」「流浪地球2」，详情链接 `/199`、`/198`。
- 搜索结果页 `/199`（流浪地球2）→ **56 条唯一 magnet**；`/198`（流浪地球）→ **29 条唯一 magnet**，都带体积（如 `[34.03GB]`）。

**优点**

- 三家里最快（0.46s），搜索是标准 GET。
- **磁力密度高**：一个影片页 29–56 条（仅次于 BD电影首发的 102 条），规格最全（DV/HDR/音轨/体积）。
- 匿名就能读到磁力，不用登录。

**缺点**

- 装了 `Ixc_login` 登录插件，**部分链接可能要登录/VIP**——落地前必须先确认登录墙范围。
- 4K 原盘为主，体积 30GB+ 居多，对用户磁盘/带宽要求高，适合做「4K 专区」而不是默认源。
- 页面混排网盘链接，解析时要排除。

**落地建议**

- 先做「匿名可读」的那部分；登录墙内的链接不要碰（项目没有凭据模型）。
- 如果只收一家且用户群偏 4K，它可以排在 BD电影首发之前；否则作为第二家、默认关闭。

### 3.4 推荐 ③：磁力熊（cilixiong.org）

**实测证据**

- `POST https://www.cilixiong.org/e/search/index.php`，参数 `keyboard=流浪地球&show=title&tempid=1&classid=1,2` → 200，「找到 3 条符合搜索条件」。
- **参数不能省**：只传 `keyboard/show/tempid` 会返回「信息提示 / 没有搜索到相关的内容」；`classid` 必须是 `1,2`。
- 详情页 `/movie/4763.html` → **4 条唯一 magnet**，带 YTS 规格和体积：`Spider-Man Brand New Day (2026) [1080p] [WEBRip] [5.1] [YTS.GG - YTS.BZ][2.6G]`。

**优点**

- 电影 + 剧集都覆盖（`/movie/`、`/drama/` 两个栏目），是三家唯一明确有剧集栏目的。
- 磁力带规格与体积，字段规整。
- 页面干净，无登录。

**缺点**

- **POST 搜索 + 隐式参数**（`classid=1,2`），比 GET 难调；参数变了就整站失效。
- **限流明显**：连续快速 POST 会读超时（实测第三次请求 25s 超时）。
- 响应 7.0s，是三家最慢的。
- 新片存在「未上映先有资源」的条目（示例是 2026 年电影的 WEBRip），质量需按分辨率/来源过滤。

**落地建议**

- provider 必须支持 POST（项目已有先例：`bangumimoe`）。
- 加请求间隔/退避，或把搜索降到「用户显式触发」而不是每次聚合都打。
- 需要剧集覆盖时优先它；只要电影可以先用前两家。

### 3.5 谨慎（2 家）

**ACG.RIP（acg.rip）**

- 站点本身质量高：动漫/OST 为主、无广告、有 RSS，社区口碑好。
- 但本机 **502 不可达**（走了代理仍失败），仓库探活是 200——网络条件依赖明显。
- 更关键的是**增量低**：项目已有 `nyaa` / `mikan` / `dmhy` / `animetosho` 四家动漫源。
- 结论：**谨慎**。等网络可达、且确实缺 ACG 资源时再评估。

**BT世界网（btsj6.com）**

- `GET /?s=流浪地球` 可用，详情页 `/subject/lldq-2019.html` 有 6 处 `.torrent` 文本 + 迅雷入口。
- 但 `down.php?...` 返回的是**同一个 HTML 页**，没有 magnet；要拿到 infohash 必须下载 `.torrent` 再解析 bencode。
- 项目目前 **0 处 bencode 解析**，加这个能力是核心层改动，不是 provider 改动。
- 结论：**谨慎**。除非同时有 2–3 家 `.torrent` only 的站值得收，否则不划算。

## 4. 网盘搜索（4 家）

### 4.1 总判断：**4 / 4 不推荐**

不是站点差，而是**数据模型不匹配**：这 4 家的产品形态是网盘搜索（夸克/百度/阿里），不是磁力索引；`TorrentResult` 没有对应字段，项目也没有「网盘」tab 或网盘下载器。硬塞进去只能变成「标题 + 外链」，既不能推送下载器，也不能做磁力健康度。

| 站点 | 本机 | 形态 | 输出 | 建议 |
|---|---|---|---|---|
| PanSou `pansou.de` | 200 / 1.5s | Next.js SPA | 网盘链接 | 不推荐（现阶段） |
| KK网盘搜 `kkso.net` | 200 / 1.3s | Vue SPA，暴露 `/api/tool/*` | 网盘链接 | 不推荐 |
| 追剧吧 `zhuiju.us` | 200 / 2.2s | 与 KK 同模板、同接口 | 网盘链接 | 不推荐 |
| 谷哥搜 `gugeso.com` | ERR（TLS 握手超时） | — | — | 不推荐 |

### 4.2 逐站

**PanSou**

### 5.4 共性风险

- **版权**：54 条全部 `copyright=high`；这类站在国内是重点打击对象，域名寿命通常很短。
- **广告/跳转**：多家自述「有广告能接受」；播放页常带跳转广告，不适合嵌进桌面应用。
- **域名漂移/同模板**：`jianyunys`/`bubu`/`tdgo`/`dyrs` 等都跳到新域名，且多家页面结构相近，疑似同一套 CMS 换皮；内容重叠，收录多家没有增量。
- **要梯子**：至少 6 家标注「需梯子」，桌面应用无法保证网络条件。

> 如果目标是「能看片」，正确做法是另做一个播放器/聚合项目；把它塞进 BT 搜索只会让产品定位变模糊。

## 6. 如果只加一家：三家候选的横向对比

| 候选 | 增量价值 | 实现成本 | 稳定性 | 字段完整度 | 综合 |
|---|---|---|---|---|---|
| **BD电影首发** | 高（中文综合影视） | 低–中（WP + 1+N 展开） | 中（单域名、有广告） | 中（无 seeders） | ★★★★ |
| **POMO** | 中高（4K 原盘，磁力密度高） | 中（登录墙待确认） | 中 | 高（体积/规格最全） | ★★★★ |
| **磁力熊** | 中高（电影 + 剧集） | 中（POST + 限流 + 慢） | 中低（7s、连续请求超时） | 中高（规格/体积） | ★★★ |

**建议顺序**

1. **先做 BD电影首发**：结构最简单（WordPress + `?s=`），磁力最密，能最快验证「中文影视源」这个假设。
2. **POMO 紧随其后**：磁力密度高（29–56 条/片），但先确认登录墙；若匿名可读的部分够用，它的性价比高于磁力熊。
3. **磁力熊放最后**：唯一明确有剧集栏目，但要先解决 POST 限流和 7s 响应。

**落地前的验证清单（建议）**

- 连续 7 天、每天 1 次探活，可用率 ≥ 90% 再动手；
- 用 20 个中文片名测搜索命中率（含冷门片、剧集、综艺）；
- 抽样 50 条磁力，确认 infohash 可解析、名称/体积能映射到 `TorrentResult`；
- 确认匿名可读（无登录墙/验证码），并记录一次真实 fixture 供离线测试；
- 观察 1 周内是否换域名；换过就先把 mirrors 准备好。

**不建议做的三件事**

1. **不要为了在线影视站改产品形态**——那需要播放器/HLS，不是 provider 能解决的。
2. **不要为 `.torrent` only 的站单独加 bencode 解析**——至少 3 家（btsj6 / btbtla / dyg22）都有同样的问题，但收益不如直接找磁力站；真要做就一次性做成核心能力。
3. **不要把榜单评分当权重**——86/126 五项全 5 分，没有区分度。
