### ⚠️ 发版资产异常（低危，未修）
`v0.3.11-beta` 的资产里**没有 `latest.yml`**，但多了 `.exe.blockmap`；`v0.3.10-beta` 相反。
怀疑是**两个 workflow 抢同一个 Release**：`build.yml` 在 tag 上用 `npm run dist -- --publish=onTag`
**自己发布**（会带 latest.yml + blockmap），而 `release.yml` 收尾时先
「Delete existing release (keep tag)」再用自己的 6 个产物重建 ⇒ 谁最后跑完谁决定资产集。
**实际影响 ≈ 0**：仓库里没有任何 `electron-updater` / `autoUpdater` 引用 ⇒ 没有自动更新在用这个文件。
真要修就得改成「单发布者」（二选一：去掉 build.yml 的 tag 触发，或让 release.yml 也上传 latest.yml）。

## M6 差分门扩到 20 家（同日晚，用户「继续」后）

**先修了一个真差异**：`subsplease` 的结果顺序。JS 用 `Object.entries()`（文档序），
`serde_json::Map` 默认 `BTreeMap`（按 key 排序）。原来只在注释里当"接受的差异"，
但差分是**逐行按下标对齐** ⇒ 顺序不同会整列错位、报上百条假差异。
修法**不引新依赖**：自定义 `Deserialize` 把顶层对象读成 `Vec<(String, Value)>`
（`MapAccess` 本来就按文档序吐 entry）⇒ 不需要 `preserve_order`/`indexmap`/改 lock。

- `dump_rust.rs` 加 4 个 spec + 分发（**`dmhy` 收 page 参数**，另三家三个参数）
- `fixtures.cjs` 加 4 条 URL 规则（subsplease 走 `/api`，其余按主机名）
- 结果（run `39731069774`）：**20 家、0 处未豁免差异、246 处命中白名单**；
  新四家逐字段全等：subsplease 90/90、dmhy 80/80、mikan 1000/1000、animetosho 75/75。
- 顺手清掉 2 处历史 warning（`bt-torznab/provider.rs` 函数体内误用 `///`、`demo.rs` 无用导入）
  ⇒ CI 现在 **0 warning**（run `39731618313`）。
