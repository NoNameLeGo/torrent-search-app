## 修掉 nyaa 的数据级 bug（JS + Rust 同轮）

上游三处 bug（原来照抄，验收口径是「与 Node 逐字段一致」）：
1. 磁力在 Link 格，代码在**名字格**里找 ⇒ `magnet` 恒 null、`needsMagnet` 恒 true，
   而 nyaa 没有 resolveMagnet ⇒ **结果里根本拿不到磁力**；
2. 名字格带 `colspan="2"` ⇒ 一行只有 8 个 td，而 JS 按 9 列读 `eq(2..5)` ⇒
   size 读到空的 Link 格、date 读到 `624.0 MiB`、**seeders 读到日期串 → parseInt = 2009**；
3. `id` 因此从名字派生而不是 hash。

修法：磁力在**整行**里找；索引 2..5 → **3/4/5/6**。两侧同轮改 ⇒ 差分门仍 22 家 0 差异
（它比的是「同一份 fixture 下两边是否相同」，不是「是否等于某个历史值」）。

⚠️ 教训：`nyaa.rs` 里有**内联单测**（`#[cfg(test)] mod tests`）也在钉旧行为，
改 provider 时必须连它一起改 —— 这次漏了，CI 红了一轮。

**同类还有两处没修**（都在 AGENTS 的上游 bug 表里，都是数据级）：
- `audiobookbay`：size 恒 null、date 被赋成整段垃圾串；
- `linuxtracker`：主表里夹着 19-td 的「展开描述行」，这些行 size/seeders 落在错误列。

## 修掉 audiobookbay 的 size/date 双丢

根因：页面用 `<br />` 分隔字段，而 cheerio/scraper 的 `.text()` **都不给 `<br>` 补换行**
⇒ 整段挤成 `Posted: 1 Sep 2026Format: … File Size: 19.24 GBs`，按 `\n` 切只有一条：
`startsWith('File Size:')` 永假（size 恒 null），`startsWith('Posted:')` 为真 ⇒ date 变成整段垃圾。

修法（两版同轮）：按**字段名**切 —— 取标签之后、下一个已知标签之前那段。
`19.24 GBs` 去尾 s ⇒ `19.24 GB`；`1 Sep 2026` 走 parse_date 的月名分支（本地零点）。
CI：audiobookbay 9/9 与 Node 完全一致。

## 搬 anirena（第 23 家）+ 给 HTTP 层补「不跟随跳转」

anirena 的磁力锚点是个 **302 到 `magnet:` 的地址**，JS 用 `maxRedirects: 0` 手动读 `Location`。
为此给 `bt-core::http` 加了两样（默认不影响任何现有 provider）：
- `TextResponse.location`（3xx 也填，那时 error 同时是 Some）；
- `HttpClient::without_redirects()`。

**踩了两个 reqwest 的坑（都值得记）**：
1. `RequestBuilder::redirect()` **不存在** —— 跳转策略只能设在 **ClientBuilder** 上（E0599）。
   所以只能造一个单独的 client 实例，不能按请求设。
2. `scraper::Dom` **不是 `Send`** —— 只要它在 `.await` 之前还被持有，整个 future 就不是 Send，
   `site!` 宏里的 `Box::pin(...)` 直接编译失败。修法：用块作用域把 href 取出来、
   让 `Dom` 先析构，再 await。

其它：日期取行属性 `data-created-ts`（unix 秒，属性**不带引号**）；分类在 `td.col-cat` 的 title 上。
测试桩加了 `oneshot_redirect()`（302 + Location），resolve_magnet 三条路径都测了。

CI：**anirena 100/100 完全一致**，23 家 0 处未豁免。
