# 端到端真机验证清单（Rust / Slint 桌面版）

> 对象：Rust 主线（crates/，单文件 exe）。这块是当前**唯一没被验证过的**部分 —— 数据源功能只经过
> 编译 + 单测，没有一次在真机上点过界面、拉过 Prowlarr 定义、搜出过结果。
> 本清单的按钮文案、状态栏文字**逐字取自代码**（crates/bt-app/ui/app.slint、crates/bt-app/src/main.rs、
> crates/bt-app/src/ui_model.rs）。文案与这里对不上，说明代码已变 —— 也是有效结果，请顺手改文档。
> 全部勾完 = 端到端验证完成；勾不上的条目请把**当时的整句状态栏文字**抄进 issue。

## 0 前置

| 项 | 事实 |
|---|---|
| 产物 | Releases 页取 BT-Search-Rust-<版本>.exe（单文件绿色版，静态链接 CRT，不需要装 VC++ 运行时）。本版本**只有 3 个产物**：这个 exe、它的 `.zip`（同一个 exe 的压缩包）、以及 `BT-Search-Tauri-Setup-<版本>.exe`（Tauri 壳，构建于 `feat/tauri`，自带 Node 后端，**不在此清单范围**）。**本清单只验 Rust 主线。** |

| 目录里的文件 | config.json（下载器）、pansou.json、indexers.json、sources.json（数据源唯一真源）、health.jsonl（每站历史 + 熔断依据）、cardigann/（目录定义缓存）、selection.csv（导出结果）。 |
| 彻底重来 | 退出应用 → 把 %APPDATA%\bt-search 整个改名或删掉（或把 BT_SEARCH_HOME 指到空目录）→ 重启。⚠️ 删 health.jsonl 会一并清掉熔断判断依据（见 §7）。 |
| 网络 | 需要外网，且能访问 indexers.prowlarr.com。 |

🔶 **需要人工准备的环境**（其余条目只用应用 + 网络）：

1. 一台能上网的 Windows（就是被验收的那台）。
2. **任一**下载器并开着：qBittorrent（WebUI 在 localhost:8080）/ Transmission（:9091）/
   aria2·Motrix（:16800 或 :6800）/ Gopeed（:9999）—— §5 用，缺了只跳 §5.1–5.4。
3. **可选** PanSou 实例（默认 http://127.0.0.1:8888）—— §3.4 用；没有就只验「连不上」分支。
4. **可选** Jackett / Prowlarr 实例（一条 Torznab feed + API key）—— §5.5 用；没有就只验「没有索引器」分支。
5. §4.5（目录成员）**不需要**本地 Prowlarr 实例：数据来自公共清单。

## 1 冷启动

### 1.1 双击 exe
- 步骤：双击 BT-Search-Rust-<版本>.exe。
- 预期：窗口 1280×832；顶栏「BT 聚合搜索 / RUST / 磁力 / 视频 / 网盘 / 设置」；搜索框占位「关键词（回车搜索）」；
  状态行「就绪」；结果区空态「一个关键词 / 扫完 N 个站点。」（N = 站点数，水印同数）；设置面板**默认收起**。
- 失败定位：进程起不来 / 报缺 DLL ⇒ S2（静态 CRT）的结论被打破，记下缺哪个 DLL；闪退看事件查看器。
- ☐ 通过：窗口出现并可用（首次 1.1–1.6 s 是已测过的常态，见 §7）。

### 1.2 首次落盘
- 步骤：关闭应用 → 看 %APPDATA%\bt-search。
- 预期：至少出现 sources.json（内置 33 条 = 28 BT + 5 影视）；config.json / indexers.json 等在对应设置保存后才出现。
- 失败定位：目录什么都没有 ⇒ data_dir 取不到 %APPDATA%（应用应仍可用，只是不落盘）。
- ☐ 通过。

### 1.3 重启不重复生成
- 步骤：再开一次。
- 预期：设置仍收起；「数据源」摘要与上次一致；没有重复条目（同 id 不会变成两条）。
- 失败定位：条目数量翻倍 ⇒ 导入/迁移路径重复 apply。
- ☐ 通过。

## 2 磁力搜索

### 2.1 一次基线搜索
- 步骤：「磁力」模式，搜索框输入 ubuntu，回车。
- 预期（状态行按顺序经历三段）：
  1. 起步：搜索中…（第 1 页 · K 家）
  2. 进行中：搜索中… d/K 家已返回 · 已 N 条
  3. 收尾：共 N 条 · X 家成功 / Y 家失败（有站返回 0 条时后缀 / Z 家返回 0 条）
  右栏「引擎扫描」d/d + 进度条到 100%，副文案「X 家返回 N 条 · Y 失败」；「本次统计」四个数字：
  命中 / 去重 / 失败 / 耗时（耗时 = **最慢那家**的 ms）；「逐站状态」每站一个 chip：✓ 12 条 / ✗ <错误串前 18 字> / … 进行中。
- 失败定位：N = 0 时状态行给归因（见 2.3）；单站 ✗ 的完整错误串在状态行，chip 上只有前 18 字。
- ☐ 通过。

### 2.2 站点开关
- 步骤：设置 → 底部「站点」行，点掉几家（标签在 ✓ 站名 / ○ 站名 之间切换）→ 再搜一次。
- 预期：点开关**不自动重搜**（有意设计）；下一次搜索状态行括号里的家数随之减少。
  全部取消后状态行「一个站点都没勾选 —— 至少勾一家再搜」，且**不发请求**。
- 失败定位：取消后该站仍出现在「逐站状态」⇒ 取消没生效（开关模型与实际 provider 集合脱节）。
- ☐ 通过。

### 2.3 空结果归因（用不可能命中的词，如 zzqqxx998877）
- 步骤：搜一个乱串，看收尾的状态行。
- 预期：三选一，且都与「站坏了」区分得开：
  - 一条都没有：K 家**全部失败** —— **网络层不通**（超时 / 连不上）… 或 **站点层拒绝**（403 / 限流 / 返回内容不认识）…
  - 一条都没有：K 家都连上了但**返回 0 条** —— 更像是站点改版了（选择器失效）
  - 一条都没有：X 家成功但没结果 / Y 家失败 / Z 家返回空
- 失败定位：三种归因互相串台（例如全都 403 却报「网络层不通」）⇒ net_failures / site_failures 计数错了。
- ☐ 通过（出现的分支与当时的网络实况相符）。

### 2.4 惰性磁力（看按钮文案区分）
- 步骤：找一行按钮写着「取磁力并推送」的（磁力在详情页的那几家），点它。
- 预期：按钮「取磁力并推送」→「解析中…」→ 成功「已推送 ✓」（同时状态行「已推送到 <kind>（HTTP 200）」）；
  失败则退回「推送到下载器」，状态行「取磁力失败：<原因>」。
- 失败定位：取磁力失败：no resolver = 那家没实现磁力解析（代码兜底文案）；其它串是 provider 自己给的；
  找不到 provider 时是「找不到站点 <id>」。
- ☐ 通过。

### 2.5 详情面板
- 步骤：点任一行的「详情」。
- 预期：右侧出现 460px 面板，从上到下 —— 标题 / meta 一行 / **2×2 指标（做种·下载·大小·文件数）** /
  来源 / INFOHASH / 磁力 /「复制磁力」/「找字幕」+ SubHD / ASSRT / 字幕库 /「关闭」收起。
  指标里缺的字段显示「—」（该站没给大小或文件数时属正常，不是 bug）。
  点「找字幕」→ 系统浏览器打开该站搜索页，状态行「已在 <站点> 搜「<片名>」」。
- 失败定位：「这一行的标题里抠不出片名，没法搜字幕」= 片名清洗不认这个标题格式；
  「打不开这个链接：<url>」= 没默认浏览器。
- ☐ 通过。

## 3 视频 / 网盘

### 3.1 切模式
- 步骤：顶栏点「视频」，再点「网盘」，再回「磁力」。
- 预期：状态行分别变「在线影视：N 条」/「网盘：N 条」/ 回到磁力那轮的状态；
  视频空态「一个片名 / 搜 5 家在线影视站。」；网盘空态「一个关键词 / 搜网盘。」；
  分页按钮「第 N 页 · 下一页」只在磁力模式出现；分类 / 排序行也只在磁力模式出现。
- 失败定位：切模式后列表被挤成一条 / 右侧空出一大块 ⇒ 布局塌陷（历史 bug：visible 改 if 的那次）。
- ☐ 通过。

### 3.2 视频搜索
- 步骤：输入一个片名（如 庆余年），回车。
- 预期：视频搜索中…（5 家）→ 四选一：
  视频搜索：N 条 / 视频搜索：0 条 / 视频搜索：N 条（K 家失败）/ 视频搜索失败：<err1>; <err2>，
  末尾可能带「，S 家疑似改版」（S = 连续 3 次空手的历史信号）。
- 失败定位：「疑似改版」是历史，不是本次错误；本次错误串在状态行里以「; 」分隔，逐条看。
- ☐ 通过。

### 3.3 打开网页
- 步骤：点某行「打开网页」。
- 预期：系统浏览器打开原站详情页，状态行「已打开：<标题>」（不内嵌播放器、不缓存）。
- 失败定位：「打不开这个链接：<url>」= open_url 失败（无默认浏览器 / url 空）。
- ☐ 通过。

### 3.4 网盘配置与探活（🔶 需 PanSou 实例）
- 步骤：设置 →「网盘」行填地址 → 点「探活」→ 点「保存」。
- 预期：成功「在线 · N 个源：a、b、c…」；失败「连不上：<url>」；
  保存后该行状态变「1 个实例：<url>」或「N 个实例（主：<url>）」（未配置时是「未配置网盘搜索（默认 127.0.0.1:8888）」）。
- 失败定位：开了 PanSou 仍「连不上」⇒ 地址少端口 / 实例要登录。
- ☐ 通过（至少有实例时的成功分支，或明确记下「无实例，仅验失败分支」）。

### 3.5 网盘搜索
- 步骤：切「网盘」，搜 流浪地球。
- 预期：网盘搜索中… → 网盘搜索：N 条 / 网盘搜索：0 条 / 网盘搜索失败：<e>；
  配了多个实例且主实例挂掉时追加「（主实例不可用，已切到 <url>）」。
  点「打开 / 复制」→ 浏览器打开网盘链接 + 提取码自动进剪贴板，状态行报提取码（无提取码时给「… · 无提取码」类文案）。
- 失败定位：「网盘搜索失败：<e>」里的 e 是实例地址或超时原因；两个实例都挂时不会假装成功。
- ☐ 通过。

## 4 数据源六行逐个

> 六行都在「设置」面板里。每行的状态文字就在按钮右边，逐条抄下来最省事。

### 4.1 导入源：Prowlarr 公共清单
- 步骤：「导入源」输入 https://indexers.prowlarr.com/master/12 → 点「导入」。
- 预期：先「导入中…」（顶部状态行「正在下载数据源配置…」）→「已导入 / 更新 N 个源」，
  有跳过时追加「，跳过 N 条不支持的」；此后「数据源」行数字变大、「成员」行整块出现。
- 失败定位：数据源导入失败：没有可用的公共索引器（只取 type=public）= 清单拿对了但筛空了；
  下载失败：<e> = 网络；不是合法 JSON / YAML 解析失败 = 拿到的不是清单（比如给了 HTML 页）。
- ☐ 通过。

### 4.2 导入源：其余三种格式 + 错误输入
- 步骤：分别贴 ① 一份 TVBox 单仓配置 URL ② 一份 LibreTV SourceList v2 URL ③ 一行一个 URL 的纯文本 ④ 一段乱码。
- 预期：①②③ 都是「已导入 / 更新 N 个源」；④ 给中文人话错误，例如
  「没解析到 sites / urls —— 这不像一份 TVBox 配置」/「没解析到 sources —— 这不像一份 LibreTV 源列表」/
  「这份配置里没有能用的源」。
- 失败定位：④ 里出现机器码（如 no_sites_or_urls）⇒ 错误码没翻译成中文，说明 import_error_text 漏了一码。
- ☐ 通过。

### 4.3 规则：贴一段 → 测试 → 保存
- 步骤：「规则」文本框贴下面这段（字段口径见 docs/SOURCES-DESIGN.md §2），先「测试」再「保存」：

    {
      "base": "https://share.dmhy.org",
      "search": { "path": "/topics/list", "method": "GET", "inputs": { "keyword": "{{ .Keywords }}" } },
      "rows": "table tbody tr:has(a[href^=\"magnet:?\"])",
      "fields": {
        "title":    { "selector": "a[href^=\"/topics/view/\"]" },
        "download": { "selector": "a[href^=\"magnet:?\"]", "attribute": "href" },
        "size":     { "selector": "td:nth-child(5)" },
        "seeders":  { "selector": "td:nth-child(6)" }
      }
    }

- 预期：测试 →「搜「<当前搜索框的词，空则 test>」拿到 N 条（<ms> ms）」；保存 →「已保存规则 <id>，下轮搜索生效」；
  同一条再存一次 →「这条规则已经在列表里：<id>（内容已更新）」。保存后搜一次，这家应出现在「逐站状态」。
- 失败定位：「测试失败：<e>」多半是选择器选不中（规则语法对、页面结构变了）；
  「不支持的 filter：<名字>（白名单：replace / re_replace / append / prepend / trim / split / regexp）」＝ 用了白名单外的 filter；
  其它：「规则缺 rows（结果行的选择器）」「规则缺 search.path（搜索路径）」「规则里的 base 必须是 http:// 或 https:// 地址」。
- ☐ 通过。

### 4.4 订阅
- 步骤：「订阅」贴一个返回源清单的 URL（可直接用 4.1 那份 Prowlarr 清单 URL，格式自动识别）→ 点「添加」（添加即立刻拉一次）→ 再点「刷新」。
- 预期：第一次「刷新 1 个订阅…」→「订阅刷新：新增 A、更新 B」；失败时追加「；失败 K 个：<订阅名>：<原因>」；
  第二次刷新应报「新增 0、更新 B」（幂等）。
- 失败定位：「还没有订阅」= 列表空（添加没成功）；「<订阅名>：空响应」= URL 回 200 但 body 空；
  「保存失败：<e>」= sources.json 写不进去。
- ☐ 通过；并且刷新前后「站点」行的 ✓/○ **一个字都不变**（订阅只换定义，不动用户开关）。

### 4.5 目录：拉取定义
- 步骤：「目录」行点「拉取定义」（只拉「已启用且没缓存」的成员）。
- 预期：先「拉取 N 个定义…」（串行 + 每站 120ms 间隔，几十个要等一会儿）→ 收尾
  「目录定义：可搜 ok / N」，后面可能依次追加：
  「；K 个结构不支持：<名字>（需要登录 / 没有行选择器 / 搜索用的是 POST …）」
  「；M 个 filter 未实现（按原样处理）：dateparse、timeparse…」
  「；失败 K：<名字>：<原因>」
  再点一次应报「N 个成员都已缓存（要重拉点「重拉全部」）」。
- 失败定位：「没有启用的目录成员（先导入 Prowlarr 清单）」= 4.1 没做或成员全关；
  「正在拉取，等这一轮结束」= 重入保护（不是卡死）；单个成员失败一定带站名。
- ☐ 通过：ok > 0，且 %APPDATA%\bt-search\cardigann\ 里出现定义文件。

### 4.6 成员：逐站开关
- 步骤：「成员」行点某一站（✓ 站名 / ○ 站名 切换）。
- 预期：打开一个**还没缓存**的站 →「已启用 <id> —— 点「拉取定义」后才会参与搜索」；
  已缓存的站 →「已启用 <id>」/「已停用 <id>」。
- 失败定位：「没找到成员 <id>」= 界面行与配置对不上（重新导入清单）；「保存失败：<e>」= 写盘失败。
- ☐ 通过：按提示再拉一次定义，搜一次，该成员出现在「逐站状态」。

### 4.7 数据源：只读摘要
- 步骤：看「数据源」那一行的文字。
- 预期：数据源 N 条（内置 33 · 导入 M · 订阅 K），X 条已关（括号里只有非零项）；空时「数据源：空（点「导入」加源）」。
- 失败定位：N 与「站点」行实际条数差得离谱 ⇒ 注册表里混进了不该计的条目。
- ☐ 通过。

## 5 下载器推送

### 5.1 探测（🔶 需本机下载器）
- 步骤：「设置」→ 下载器行点「探测」。
- 预期：状态行「正在探测本机下载器…」→ 命中时四个输入框被填好、行内「已探测到 qbittorrent」、状态行「探测到下载器：qbittorrent」；
  没命中：「没探测到（试试手填地址）」+「没探测到本机下载器」。
  探测是 9 条固定候选、按顺序命中第一个即返回：qB localhost:8080（admin/adminadmin、admin/空）、127.0.0.1:8080、
  localhost:8081；TR localhost/127.0.0.1:9091；aria2 :16800/jsonrpc、:6800/jsonrpc；Gopeed :9999。
- 失败定位：qB 开着却探不到 ⇒ WebUI 端口不是 8080，或开了 IP 白名单/CSRF 保护。
- ☐ 通过。

### 5.2 保存配置
- 步骤：先点「qB」/「TR」/「aria2」/「Gopeed」→ 填地址、用户名、密码（token 型填在「密码 / token」框）→ 点「保存」。
- 预期：「下载器已保存：qbittorrent」；落盘失败时后面括号带原因，但**本次会话仍可用**。
- 失败定位：「请先填下载器地址」/「地址不合法：只接受 http:// 或 https://」/
  「无法识别的下载器类型（界面状态异常）—— 请重开设置面板再试」。
- ☐ 通过。

### 5.3 单条推送
- 步骤：搜一次，点某行「推送到下载器」（内联磁力的那几家）。
- 预期：「已推送到 qbittorrent（HTTP 200）」，按钮变「已推送 ✓」，下载器里真出现该任务。
- 失败定位：「推送失败：请求下载器失败 (…)」= 网络/超时；
  「推送失败：下载器返回 HTTP 403」= qB 未授权（IP 白名单/登录失败被挡）；
  「推送失败：登录失败（用户名或密码错误）」= 凭据错。
- ☐ 通过（端到端的关键一环：任务真的进了下载器）。

### 5.4 批量 / 导出 / 复制
- 步骤：勾选两行（底部浮层「已选 2 项」）→「批量推送」→「导出 CSV」→「复制磁力」。
- 预期：批量逐行推送；导出「已导出 N 条 → <数据目录>\selection.csv」
  （UTF-8 BOM，Excel 直接认中文；**固定路径，没有另存为对话框**）；
  复制「已复制 N 条磁力」，有没解析的会追加「（K 条无磁力已跳过）」。
- 失败定位：「先勾选要推送的结果」/「先勾选要导出的结果」/「没有可复制的磁力（没勾选，或选中的都还没解析）」；
  「取不到 %APPDATA%，没导出」= 数据目录不可写。
- ☐ 通过。

### 5.5 索引器（Torznab，🔶 需 Jackett/Prowlarr 实例）
- 步骤：索引器行填 名字 / Torznab 地址 / API key（或把带 ?apikey= 的 Copy Torznab Feed 链接整条贴进地址框，key 会被自动抠出来）→ 点「添加」。
- 预期：行内状态「已配置 1 个：<名字>」，下面出现「✓ <名字>」+「停用」按钮；
  搜一次词，这家出现在「逐站状态」；点「停用」→「已配置 1 个（1 个已停用）：…」，「启用」可恢复。
- 失败定位：「请先填 Torznab 地址」/「地址不合法：只接受 http:// 或 https://」；
  搜索里报错就是该索引器自己的错误串（按名字认出是哪家）。
- ☐ 通过。

## 7 已知会被误判为失败的现象

| 现象 | 为什么不是 bug | 怎么办 |
|---|---|---|
| 某站开关 ✓，但搜索里没有它 | **熔断**：最近连续 3 次空手（0 条**或**报错都算）就临时退出搜索；sources.json 里的 enabled 一个字没改 | 等它有一次命中自动回来；急就删 health.jsonl。目录成员同样按 prowlarr:<id> 判 |
| 成员开关 ✓ 却不参与搜索 | 定义还没落地：缓存里没有就不进 provider 集合 | 点「拉取定义」；操作时状态行已提示「点「拉取定义」后才会参与搜索」 |
| 目录站的日期是原始文本 | Cardigann 只实现 7 个 filter，dateparse / timeparse / andmatch / sort 没做，未知 filter 按原样处理 | 不是失败；标题 / 磁力 / 做种正常。拉取时会报「M 个 filter 未实现（按原样处理）」 |
| 「结构不支持」的成员不落盘 | 需要登录 / POST / 没有 rows 的定义结构上跑不了 | 预期行为；计入「K 个结构不支持：<名字>（原因）」，不是下载失败 |
| 一条都没有 + 「都连上了但返回 0 条」 | 选择器失效（站点改版），不是「这个词真没资源」 | 该站要改 provider 或规则，本机无解 |
| 部分站 ✗ 且错误是 403 / 超时 | 站点常态（本机 DNS 污染、站点反爬）；CI 的数据中心 IP 更严重 | 记下站名即可；provider-health / live-smoke 的 CI 结果更有参考价值 |
| 首次启动 1.1–1.6 s | Defender 首扫 + 冷盘读约 20 MB | 已知，第二次启动明显快 |
| 「下一页」是灰的 | has_more 来自引擎，不是「这页满了」的猜测 | 真没有下一页 |
| 导出找不到文件 | 刻意没引 GUI 依赖，没有另存为对话框 | 固定 %APPDATA%\bt-search\selection.csv，状态行给了全路径 |
| 网盘搜索直接报失败 | 默认端点 127.0.0.1:8888 上没装 PanSou | 要么装实例，要么只验 §3.4 的「连不上」分支 |
| 「疑似改版」和正常结果同时出现 | 它是历史信号（连续 3 次空手），不是本次错误 | 看本次结果与状态行里的错误串 |
| 状态行停在「d/K 家已返回」 | 慢站还没回（各家并行，最慢的决定耗时），超时后按失败计 | 等收尾；卡很久就看是哪个 chip 还是「…」 |
| 索引器加了却搜不到 | 索引器可以在「已停用」状态；或该索引器本身报错 | 看行内是 ✓ 还是 ✗，再看状态行里它的错误串 |
